2. HOW THE WEBSITE WORKS — COMPLETE WORKFLOW
================================================================================

STEP 1: SERVER STARTUP
───────────────────────
  - Running: `node server.js` or `npm start`
  - Express.js server starts on Port 3000
  - Static files from /public/ are served to browser
  - Two route groups are mounted: /api (apiRoutes) and /api/docs (Swagger)
  - Two background jobs start automatically:
    a) Scheduled Scheme Ingestion (weekly refresh from government portals)
    b) Scheduled EMI Reminders (daily check of loans, creates notifications)

STEP 2: BROWSER LOADS THE APP
───────────────────────────────
  When a farmer opens http://localhost:3000 or the deployed URL:
  1. index.html is served
  2. Browser loads CSS (styles.css), core JS (app.js), data files
  3. Service Worker (sw.js) installs and pre-caches the application shell
     → After first load, the app works OFFLINE with no internet required
  4. different_languages.js loads (25 language metadata + English base strings)
  5. schemes_data.js loads (679 schemes for offline scheme browsing)
  6. categories_data.js loads (15 national categories)
  7. manifest.json makes the app installable as a PWA on Android, iOS, Windows

STEP 3: FARMER USES THE APP
─────────────────────────────
  The app has 4 main sections accessible via the navigation bar:

  A) HOME PAGE
     - Hero banner with statistics (schemes, languages, farmers helped)
     - 15 scheme category cards (translated dynamically based on language)
     - "How It Works" section explaining 4 steps

  B) ELIGIBILITY CHECKER
     - Farmer enters: Crop Type, Annual Income, Locality, Land Size,
       Land Ownership, Social Category, and Optional: Aadhaar, KCC status
     - The "Check Eligibility" button calls POST /api/recommend
     - Backend runs the Multi-Factor Scoring Engine
     - Results return ranked, scored schemes with eligibility explanations

  C) GOVERNMENT SCHEMES BROWSER
     - All 679 schemes rendered from local schemes_data.js (instant, no API call)
     - State filter dropdown (All India + 21 states)
     - Category explorer (15 categories with hero images, scheme counts)
     - Document checklist modal for any scheme
     - "Apply" button adds scheme to loan tracker

  D) MY LOANS & EMIS TRACKER
     - Shows active and ended loan records (from GET /api/loans)
     - EMI payment progress bars with amount paid vs. due
     - "Pay EMI" button to record partial or full payments
     - Notifications for upcoming EMI due dates (7 days and 1 day warning)

STEP 4: OFFLINE & PWA BEHAVIOR
────────────────────────────────
  - Service Worker caches all static assets on first install
  - Scheme browsing, eligibility checking (with cached data), and EMI tracking
    work fully offline
  - When reconnected, API calls sync to backend for fresh data
  - App can be installed via "Install App" button → appears as native app on phone

STEP 5: LANGUAGE SWITCHING
────────────────────────────
  - Top navigation has "English" language selector button
  - Click → Language modal opens showing 25 Indian language cards
  - Farmer selects language (e.g. Hindi / Punjabi / Tamil)
  - If English: applies base strings instantly
  - If already fetched before: applies from memory instantly (0ms)
  - If new language: subtle shimmer animates on button, calls POST /api/translate
    with all 189 UI strings in one batch request, caches the response,
    then swaps all UI text in-place without reloading the page
  - Category cards, loan labels, scheme badges all change to selected language
  - Language choice is saved in localStorage (remembered on next visit)

────────────────────────────────────────────────────────────────────────────────
API 1: SCHEME RECOMMENDATION & ELIGIBILITY
────────────────────────────────────────────────────────────────────────────────

Endpoint : POST /api/recommend
Purpose  : Evaluates farmer's profile against all 679 government schemes,
           scores them on 5 weighted factors (0–100 scale), and returns them
           ranked from Best Match to Good Alternatives to Ineligible.

Rate Limit: 60 requests per 5 minutes per IP

Request Body (JSON):
{
  "cropType"      : "rice",          ← Required. Crop being grown
  "annualIncome"  : 120000,          ← Required. Annual income in INR
  "landSizeAcres" : 2.5,             ← Optional. Defaults to 2.0 acres
  "district"      : "Ludhiana",      ← Optional. For state-based matching
  "state"         : "Punjab",        ← Optional. Scheme state filter
  "landOwnership" : "owner",         ← owner / tenant / sharecropper / leaseholder
  "category"      : "general",       ← general / sc / st / obc / women
  "hasAadhaar"    : true,            ← Aadhaar linking status
  "hasKcc"        : false,           ← Existing Kisan Credit Card
  "existingLoans" : 50000            ← Outstanding debt for DTI calculation
}

Response:
{
  "success"      : true,
  "count"        : 15,
  "tierSummary"  : { "topRecommended": 1, "goodAlternatives": 10, "moderateFits": 4 },
  "debtCapacity" : { "maxSafeBorrowingLimit": 75000, "baselineDTI": 22.5, ... },
  "schemes"      : [
    {
      "id"           : "kcc",
      "name"         : "Kisan Credit Card (KCC) Crop Loan",
      "score"        : 94,
      "tier"         : "TOP_RECOMMENDED",
      "badgeText"    : "★ Top Recommended",
      "eligible"     : true,
      "matchReasons" : ["Eligible for your OWNER landholding status", ...],
      "debtSafety"   : { "status": "SAFE", "newEMI": 2340, "newDTI": 28.1 },
      "baseInterestRate"      : 9.0,
      "subsidizedInterestRate": 4.0,
      "maxLoanAmount"         : 300000,
      "highlights"   : ["Zero collateral up to ₹1.6 lakh", ...],
      "documents"    : ["Aadhaar Card", "Khasra-Khatauni", ...],
      ...
    },
    ...
  ]
}

SCORING ENGINE — 5 WEIGHTED FACTORS:
  Factor 1: Eligibility Match         (35% weight) — Land, income, ownership, category
  Factor 2: Loan Amount Fit           (25% weight) — Whether scheme limit meets need
  Factor 3: Interest Rate             (20% weight) — Lower rate = higher score
  Factor 4: Crop & State Alignment    (10% weight) — Crop suitability, state priority
  Factor 5: Strategic Fit             (10% weight) — Additional subsidies, special benefits

SEQUENCE GUARANTEE: Results always return in this strict order:
  Position 1    : Single BEST MATCH (highest overall score)
  Positions 2-11: UP TO 10 Good Alternatives (eligible, score ≥ 40)
  Positions 12+ : Moderate Fits (partial eligibility, score 20–39)
  End of list   : Ineligible schemes (shown for awareness, clearly labelled)

────────────────────────────────────────────────────────────────────────────────
API 3: LOANS TRACKER
────────────────────────────────────────────────────────────────────────────────

Endpoint  : GET /api/loans?status=all|active|ended
Purpose   : Returns all loan records with enriched financial calculations
Response includes: totalBorrowed, totalPaid, totalDue, totalMonthlyEmi,
                   activeCount, endedCount, enriched per-loan data

Endpoint  : POST /api/loans
Purpose   : Add a new loan/scheme to the tracker
Body      : { schemeName, principalAmount, interestRate, tenureMonths,
              bankName, paidAmount, dueDate, cropOrPurpose, ... }

Endpoint  : PUT /api/loans/:id/payment
Purpose   : Record a payment made towards a loan
Body      : { amount: 5000, note: "Monthly EMI" }
Behavior  : Auto-marks loan as "Ended" when fully paid

Endpoint  : PUT /api/loans/:id/status
Purpose   : Toggle loan status between Active and Ended

Endpoint  : DELETE /api/loans/:id
Purpose   : Remove a closed/ended loan from tracker
PROTECTION: Active loans with remaining due amount CANNOT be deleted
            Returns HTTP 403 Forbidden to prevent accidental data loss

FINANCIAL CALCULATIONS (all done on backend):
  EMI Formula    : [P × r × (1+r)^n] / [(1+r)^n – 1]
  where P = principal, r = monthly interest rate, n = tenure months
  DueAmount      : Total with interest – Amount paid
  PercentPaid    : (paidAmount / totalWithInterest) × 100

────────────────────────────────────────────────────────────────────────────────
API 4: RUNTIME TRANSLATION API
────────────────────────────────────────────────────────────────────────────────

Endpoint  : POST /api/translate
Purpose   : Translate a batch of UI strings or dynamic content to any of
            25 supported Indian languages in a single HTTP call

Request Body:
{
  "strings"   : { "navHome": "Home", "checkElig": "Check Eligibility", ... },
                  OR use "texts" for array input: ["Home", "Check Eligibility"]
  "from"      : "en",       ← Source language (default: English)
  "to"        : "hi",       ← Target language code (hi, pa, mr, ta, te, ...)
  "isDynamic" : false        ← If true: bypass cache (for live scheme details)
}

Response:
{
  "success"      : true,
  "translations" : { "navHome": "होम", "checkElig": "पात्रता जांचें" },
  "from"         : "en",
  "to"           : "hi",
  "stats"        : { "total": 2, "cached": 2, "translated": 0, "provider": "offline" }
}

BATCH STRATEGY: All 189 UI strings are sent in ONE single request, not one per string.
This minimizes API calls and billing cost.

PROVIDER CHAIN (tries in order):
  1. Google Cloud Translation API (if GOOGLE_TRANSLATE_API_KEY is set in .env)
     - REST: POST https://translation.googleapis.com/language/translate/v2
     - Pricing: First 500,000 characters/month FREE; then $20 per 1M characters
     - Latency: 80–200ms (Google Edge Network)
  2. Bhashini API — Government of India (if BHASHINI_API_KEY + BHASHINI_USER_ID set)
     - REST: POST https://dhruva-api.bhashini.gov.in/services/inference/pipeline
     - Pricing: FREE for public-interest, government-backed apps
     - Latency: 300–800ms
     - Registration: https://bhashini.gov.in
  3. Built-in Offline Engine (default — no credentials needed)
     - Uses core agricultural terminology dictionary
     - Provides graceful fallback so app never shows blank text

CACHE SYSTEM:
  - Type: Minimal-storage LRU (Least Recently Used) Hash Cache
  - Key format: First 16 hex chars of SHA-256(sourceText) + ":" + targetLang
    Example: "5c74c673f28b37b8:hi"
  - TTL: 30 days (UI strings rarely change)
  - Max size: 5,000 entries (auto-evicts oldest on overflow)
  - Dynamic content (isDynamic: true): NEVER cached — always fresh
  - Persistence: Saved to src/data/translationCache.json (survives server restart)
  - Cache hit: Returns instantly (0ms API call)
  - Cache miss: Calls provider once, stores result, serves response

SINGLE SOURCE OF TRUTH:
  - All 189 base English UI strings are in src/data/strings.json
  - Frontend loads these via public/different_languages.js
  - Previous approach: 4,456 lines of hardcoded per-language copies (350 KB)
  - New approach: 1 source file + on-demand runtime translation (12 KB, 96.5% smaller)

    { "schemeId": "kcc", "schemeName": "Kisan Credit Card", "sourceUrl": "https://..." }

HOW RAG WORKS:
  1. Query Analysis: Keyword and attribute scoring against 679 schemes
  2. Retrieval: Top 3 most relevant schemes selected
  3. Grounding: Answer constructed ONLY from retrieved scheme data
  4. Citation: Source links included for verification
  5. Language: Response in the same language as query (Hindi / English / etc.)
  6. Strict Policy: If data not found in DB, says "not found" — never guesses

Endpoint  : POST /api/vault/reset
Purpose   : Resets the vault password (existing documents re-encrypted with new key)

Endpoint  : GET /api/vault/status
Purpose   : Returns vault lock status and document count without decrypting

ENCRYPTION DETAILS:
  Algorithm : AES-256-GCM (Advanced Encryption Standard, 256-bit, Galois/Counter Mode)
  Key Derive: PBKDF2 with 100,000 iterations and SHA-256 (industry standard)
  Salt      : Random 16 bytes per vault (never reused)
  IV        : Random 12 bytes per encryption (ensures unique ciphertext)
  Auth Tag  : 16-byte GCM authentication tag (detects any tampering)
  PASSWORD TYPES:
    - Word   : Passphrase (e.g. "mysecret")
    - Number : 4-6 digit PIN (e.g. "4729")
    - Pattern: 3×3 grid dots (stored as sequence e.g. "0,1,4,7,8")

SECURITY GUARANTEE:
  - Opening with any wrong password returns HTTP 401
  - No brute-force pattern — vault locked with a single hash verifier
  - Documents stored in two mirrored locations for durability

4. PROGRESSIVE WEB APP (PWA) — HOW IT WORKS
================================================================================

KisanSahay is a full PWA, which means:

1. INSTALLABLE (like a native app)
   - "Install App" button appears in header and in the Switch Profile panel
   - On Android: Opens "Add to Home Screen" prompt
   - On iPhone: "Share → Add to Home Screen"
   - On Windows/Mac: Browser install button in address bar
   - After install: App icon appears on device, opens in standalone window

2. OFFLINE CAPABLE
   Service Worker Strategy:
   - CACHE-FIRST: static files (HTML, CSS, JS, images) — instant loads
   - NETWORK-FIRST: API calls (/api/*) — fresh data when online
   - FALLBACK: Cached data served when network fails
   Pre-cached Assets: index.html, styles.css, app.js, scheme data, icons

3. WEB PUSH NOTIFICATIONS
   - Browser asks permission on first visit
   - Service Worker handles push events in background (even when app is closed)
   - Farmer receives EMI reminders even when phone screen is off

4. QR CODE SHARING
   - App generates a QR code of its URL
   - Farmers can share with family members to install on their devices

5. INTERNET SPEED MONITOR
   - Live WiFi signal indicator in top-left corner of navigation bar
   - Color coded: Green (>5 Mbps good) / Yellow (1–5 Mbps moderate) / Red (<1 Mbps slow)
   - Updates every few seconds using browser Performance API

5. SECURITY FEATURES SUMMARY
================================================================================

1. Rate Limiting
   - General APIs: 200 requests per IP per 15 minutes
   - Eligibility API: 60 requests per IP per 5 minutes
   - Returns HTTP 429 Too Many Requests on violation

2. Active Loan Protection
   - Active loans with remaining balance CANNOT be deleted (HTTP 403 Forbidden)
   - Prevents accidental data loss; only fully-paid loans can be archived

3. Document Vault Encryption
   - AES-256-GCM authenticated encryption
   - PBKDF2 key derivation (100,000 iterations)
   - Wrong password: returns authentication failure, no partial data leaked

4. OTP Expiry
   - All OTPs expire after exactly 5 minutes
   - Stored only in server memory (not in database)
   - No reuse allowed after verification

5. Document Checklist Gate
   - Loans applied through scheme modal require checklist completion
   - Cannot apply for scheme without ticking required documents

6. Input Validation Middleware
   - All POST/PUT endpoints validate required fields
   - Income must be numeric and positive
   - Land size must be non-negative number

7. RFC 7807 Error Responses
   - All errors follow standard JSON problem format:
     { "type": "...", "title": "...", "status": 400, "detail": "..." }

7. HOW TO RUN LOCALLY
================================================================================

Prerequisites:
  - Node.js v18+ installed
  - npm installed

Commands:
  1. Clone the repository
     git clone https://github.com/samirahamed-27/KisanSahay.git

  2. Navigate into project folder
     cd KisanSahay

  3. Checkout the feature branch
     git checkout veersingh/feature

  4. Install dependencies
     npm install

  5. Start the server
     npm start        ← Runs: node server.js
     OR
     npm run dev      ← Runs: node --watch server.js (auto-restarts on changes)

  6. Open in browser
     http://localhost:3000

  7. Open API documentation
     http://localhost:3000/api/docs

  8. Run automated tests
     npm test          ← Runs all 48 test suites

  Create a .env file in the project root:

  GOOGLE_TRANSLATE_API_KEY=your_gcp_translation_api_key
  GOOGLE_TTS_API_KEY=your_gcp_tts_api_key
  TRANSLATION_PROVIDER=google         ← or "bhashini" or "offline"
  BHASHINI_API_KEY=your_bhashini_key
  BHASHINI_USER_ID=your_bhashini_user_id
  PORT=3000

  Without these keys, the app runs perfectly using built-in offline fallback.
